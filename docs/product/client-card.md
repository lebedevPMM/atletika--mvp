# Фитнес-Карта Клиента (ClientCard)

> **Продуктовое описание сущности**
> Последнее обновление: 2026-03-16

---

## Что это

Фитнес-Карта Клиента — центральная сущность приложения Atletika+. Это единая точка правды по каждому клиенту клуба, которую используют все три роли: клиент, тренер и методист.

Карточка привязана к паре "клиент + клуб" — один человек может иметь карты в нескольких клубах сети.

## Зачем нужна

**Проблема:** Информация о клиенте разбросана — абонемент в одном месте, здоровье в другом, записи в третьем. Тренер перед занятием не знает: какие у клиента противопоказания? сколько ПТ осталось? когда был последний раз?

**Решение:** Все данные — в одном месте, но показываются по-разному в зависимости от роли.

## Источник требований

- `Приложение.pdf` — схема взаимодействия тренер-клиент-методист
- 82 PDF спецификации в `requirements/` (ключевые: L5617-5694, L2731-2870, L4071-4292)

## Кто видит что

### Тренер (основной потребитель)

Тренер открывает карточку клиента **перед занятием** или при работе с клиентом. Видит:

| Блок | Что показывается | Зачем |
|------|-------------------|-------|
| **Профиль** | Имя, фото, возраст, теги (Новичок, ПТ, Сколиоз) | Быстрая идентификация |
| **Абонемент** | Тариф, статус, срок, заморозка | Знать может ли клиент заниматься |
| **Остатки услуг** | ПТ: 5/10, Групповые: безлимит, СПА: 2/5 | Главный вопрос: "сколько осталось?" |
| **Купленные пакеты** | Активные пакеты с остатками | Что клиент оплатил |
| **Ближайшие записи** | 1-3 записи с датой/временем/типом | Контекст предстоящих занятий |
| **Визиты** | За 30 дней, последний визит, неявки, streak | Регулярность и вовлечённость |
| **Противопоказания** | Бейдж + детали при раскрытии | Безопасность (P0) |
| **Заметки** | Свои + других тренеров | Контекст между занятиями |

### Клиент (просмотр своей карты)

Клиент видит **свою** карточку — упрощённый вид:

| Блок | Что показывается | Зачем |
|------|-------------------|-------|
| **Мой план** | Текущий тренировочный план, цель, прогресс % | Мотивация и ориентир |
| **Прогресс** | Вес: -2.3 кг, Талия: -3 см (дельты) | Видимый результат |
| **Здоровье** | Противопоказания, visibility тумблеры, consent | Контроль над своими данными |
| **Записи** | Ближайшие 1-3 | Что запланировано |

### Методист (аналитика и контроль)

Методист видит карточку клиента **через список тренера** — для контроля качества:

| Блок | Что показывается | Зачем |
|------|-------------------|-------|
| **Всё что видит тренер** | + | Полная картина |
| **Тренировочный план** | Может ревьюить и корректировать | Контроль качества программ |
| **Health Profile** | Полный доступ к изменению | Управление медицинскими данными |

## Состав данных

### Грузится сразу (тонкий агрегат)

- **Личная информация** — ФИО, телефон, дата рождения, пол, аватар, теги, контакт для экстренных случаев
- **Абонемент** — статус, тариф, срок действия, авто-продление, заморозка, лимиты услуг (ПТ/группы/СПА)
- **Профиль здоровья** — противопоказания, травмы, ограничения, лекарства, аллергии, видимость для тренера/методиста, согласие на обработку, подключённые источники (Apple Health, Google Fit, DEXBEE, MY-ZONE)
- **Сводка визитов** — всего визитов, за 30 дней, последний визит, неявки, streak, среднее в неделю
- **Сводка прогресса** — вес старт/текущий/дельта, талия старт/текущая/дельта, тренд

### Грузится по запросу (при переходе на таб)

- **Купленные услуги** — название, тип, остаток/всего, статус, срок
- **Ближайшие записи** — название, дата, время, тип, тренер, зал, статус
- **Замеры тела** — дата, вес, грудь, талия, бёдра, кто измерял
- **Тренировочный план** — название, цель, тренер, даты, недели, прогресс, чекпоинты
- **История визитов** — дата, тип, название, тренер, длительность, статус
- **Заметки** — автор, роль, текст, дата

## Приоритеты реализации

### P0 — Must-Have (реализуем сейчас)

1. Личная информация клиента
2. Абонемент + лимиты услуг
3. Купленные пакеты
4. Ближайшие записи
5. Профиль здоровья (противопоказания, visibility, consent)
6. Заметки тренера/методиста
7. Сводка визитов

### P1 — Should-Have (следующий шаг)

1. Тренировочный план + чекпоинты
2. Замеры тела (вес, объёмы)
3. Сводка прогресса
4. Подключённые источники здоровья

### P2 — Post-MVP1

1. Биоимпеданс (подробный состав тела)
2. Батарея фитнес-тестов
3. Фото до/после
4. AI рекомендации

---

## Что НЕ входит в MVP1

- Детальный трекер упражнений (сеты/повторы/веса)
- Биоимпеданс-панель
- Scoring фитнес-тестов
- Фото до/после
- AI рекомендации
- Ежедневный ввод данных клиентом
- Медицинские советы и диагнозы
- Редактирование личных данных тренером (только через ресепшн)
- Встроенное расписание в карточку

## Пользовательские сценарии

### Сценарий 1: Тренер перед занятием

1. Тренер открывает детали занятия
2. Тапает по аватару клиента
3. Видит карточку: профиль + абонемент + остатки + противопоказания + заметки
4. Замечает бейдж "Сколиоз" — корректирует программу
5. После занятия добавляет заметку

### Сценарий 2: Клиент заполняет здоровье

1. Клиент заходит в Профиль → Здоровье
2. Отмечает противопоказания (чекбоксы)
3. Описывает травмы и ограничения
4. Настраивает видимость (тренер: да, методист: да)
5. Даёт согласие на обработку данных здоровья

### Сценарий 3: Методист проверяет клиента

1. Методист открывает профиль тренера
2. Переходит к списку клиентов тренера
3. Открывает карточку конкретного клиента
4. Видит план, прогресс, заметки
5. При необходимости корректирует план или добавляет свою заметку

## Связь с PDF-схемой (Приложение.pdf)

Карточка клиента = центральный узел в схеме "Тренер-Клиент-Методист":

```
Отдел продаж → Клиент получает карту
     ↓
Чек-ап (CheckupScreen) → HealthProfile заполнен
     ↓
Вводная ПТ → TrainingPlan создан тренером
     ↓
Тренировки → VisitRecord[], ClientNote[]
     ↓
Контрольные точки → BodyMeasurement[], ProgressSummary
     ↓
Методист → Ревью плана, контроль качества
     ↓
Клиент → Видит прогресс в ClientCardScreen
```

Внешние интеграции (P1): DEXBEE, MY-ZONE → HealthSources → автоматические метрики.
